## Baseline and scope
Based on the supplied v1.5 package (which used live commit 9b16772). Merge the patch into the actual current deployment branch; do not overwrite agent changes or deployment settings. No new dependency. Existing PWA, admin login, security controls, direct mode, private assistant confirmation flow and language support remain in place.

## What's implemented
- EN/ES/FR surf coaching landing page and metadata (six routes per language; 18 total). Internal links from homepage and service pages, founder/local identity and Service structured data. Existing URLs are unchanged. Coaching and lessons for all levels; group lessons as social and potentially less costly. Playa Bonita remains base, Cosón is nearby local coast, no guaranteed waves/spot. No unverified superiority, prices, claims about safety, inventory, exact years of experience or reviews. `src/lib/knowledge.ts` centralises assistant facts and voice. Add only owner-approved facts.
- Public assistant initial Learn/Improve/Group/Local waves/Rental/Shop choices; distinguishes informational/out-of-scope vs enquiry; prompt minimises questions. Review includes optional duration, private/shared/either, custom message and email. Public API can read owner-approved group projections and a coarse overlap check (only generic hint). No private event times, notes, identities, data writes or binding reservations. Existing direct WhatsApp/email fallback remains; normal direct mailto contact is not logged by the website.
- Email channel saves exact approved message, then sends via Resend to configured owner email; Reply-To is customer address. Sender is verified Península address, never spoof customer. Cristian replies from his real mailbox. Admin has original approved copy and status (accepted for sending vs unconfirmed); no two-way mailbox sync. No mail delivery guarantee, no email sent before approval. Customer must supply valid email. Custom note optional in either channel. Idempotent submission; persisted message is source of email payload; rate-limited retry claim, max five attempts and 15-second cooldown; same idempotency key, 23h cutoff to stay within provider 24h window. A failed/unconfigured email does not delete saved enquiry; retry or direct contact. Do not promise final mailbox delivery from API acceptance.
- Admin optional expanded notes, payment status and per-event reminder; linked enquiry details visible in event editor. Private assistant can propose full revised note with explicit confirmation, no write on interpretation. Existing event/overlap snapshot guard retained. Migration expires only old pending proposals so they cannot apply with outdated row schema. No bookings or messages removed. No online payments or accounting.
- Settings for scheduled reminder email, default lead time, morning email summary and optional prepared WhatsApp enquiry email alert. New email enquiries themselves arrive in Cristian's actual mailbox and can trigger his normal phone mail notifications. WhatsApp email alerts default off. Reminder cron endpoint is implemented but intentionally not scheduled or enabled by default; protected by CRON_SECRET. It checks current schedule, hours, preferences, future events, receipts, and provider idempotency. No private notes in reminder emails. Reminder may be late or skipped during quiet hours, outages, or if calendar time has passed. One reminder per event start (moving changes key); scheduling is approximate, not guaranteed.

## Phase 2: native PWA push, after phase 1 verification
The PWA remains installable and network-only for private data. Native app push is intentionally NOT implemented in v1.6. npm registry was unavailable, so a new Web Push dependency and lockfile could not be installed/tested safely. Build next on deployed v1.6: use maintained Web Push package, VAPID keys (private server-only); owner-authenticated device subscription registration/removal, service-only RLS table, explicit user permission, service-worker `push` and `notificationclick` to `/admin`, no personal details in payload. Trigger new email enquiry alert only after save and lesson reminders via scheduled worker; deduplicate per event/device, remove invalid subscriptions on 404/410, honour global preferences and quiet hours; avoid double alerts from mail/WhatsApp. Test on installed iPhone/iPad and Android, logout and revocation, no caching private data. Use email reminders meanwhile. No subscriptions or new services required for phase 1 beyond existing Resend and hosting usage.
