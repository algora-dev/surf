# Península v1.4 — enquiry mode and resilience

## Scope
A small update to v1.3, preserving the approved design, fifteen localized public routes, SEO, private admin assistant, calendar, existing inbox and group matching. No new dependencies or external accounts. The admin Settings / Ajustes page has a bilingual, confirmed selector for Smart assistant / Asistente inteligente and Direct WhatsApp / WhatsApp directo. The demo setting is browser-local only; factory reset restores smart as the demo default.

## Deployment / merge order
1. Branch from your currently deployed v1.3 repository, merge `Peninsula_v14_Update.patch` (or compare the v1.4 full source archive), retaining any agent changes, credentials, deployment configuration and lockfile. Review conflicts rather than overwriting deployed files. Update the lockfile with `npm install` as the package version changed, then commit it.
2. In the dedicated Península Supabase project, apply `supabase/upgrade-v14.sql` **after** the existing v1.1 and v1.2 migrations. Never use QuoteCore+ or rerun unrelated migrations. The migration is additive, idempotent, and seeds `smart` only when no row exists. It creates a private singleton table `business_settings` with RLS and service-role-only read/write grants. No calendar or enquiry records are modified. The existing admin auth and same-origin checks protect the update action. No public write endpoint exists.
3. Keep preview protection and `SITE_INDEXABLE=false` during testing. Existing environment variables remain unchanged. If `OPENAI_API_KEY` is missing, public mode is effectively direct even if the stored choice is smart. The admin shows this condition. A valid-looking key does not guarantee a working API; runtime failures still offer direct contact.
4. Run `npm test`, `npm run typecheck`, `npm run build`. Deploy the preview. Test real Supabase, auth and OpenAI integration before merging to production.

## Behavior
- All shared booking CTAs and the floating chat button fetch `/api/enquiry-mode` on click, without caching. If smart is enabled and the backend is configured, open the existing concierge. Otherwise navigate directly to a service-specific localized `wa.me` link. The original anchor URL is a direct link, so no-JavaScript, modified clicks and link-copying also work. Direct navigation uses the same tab after async mode resolution to avoid popup-blocker issues. The footer WhatsApp and email remain unconditional contact routes.
- Settings retrieval is bounded (2.5 seconds server / 3.5 seconds browser). Missing table, missing record, invalid value, missing key, timeout, or unavailable settings all fail open to direct contact. A database outage may prevent saving a new admin setting, but visitors can still use WhatsApp.
- The public AI endpoint checks the effective mode before quota use and again immediately before sending to OpenAI. The public concierge-submit and legacy-form endpoints also reject new submissions while direct mode is effective. In-flight requests that already passed the check may finish; toggling cannot undo a previously submitted enquiry or cancel a remote model request already underway. Existing saved records remain untouched.
- The chat and review screens always expose direct WhatsApp/email links. On AI, network or save errors, the customer can review and copy the fallback message containing their original typed details (including a failed turn) or the approved summary. The legacy form retains submitted details if saving fails. Links are never auto-sent. No direct enquiry is automatically stored, and WhatsApp delivery cannot be verified. For exceptionally long messages or unsupported WhatsApp URLs, copy/paste is available on error.
- The private calendar assistant and voice endpoint are not gated by the public setting. Existing booking state, sessions, calendar events, availability rules and inbox stay unchanged.
- Settings changes are confirmed before the authenticated write, persisted across devices, and applied on the next public CTA click. Cancel performs no write. Old open chat tabs get the direct fallback on their next request. This is not a global automatic mode switch on a transient failure: it leaves the owner's stored choice intact.

- Test unauthenticated/unauthorized admin mutation and invalid mode. Confirm the demo switch and factory reset are browser-local, not connected to real records. Ensure no database reset is enabled in production.
